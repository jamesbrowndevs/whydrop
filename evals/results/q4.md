## Rejected hypotheses (tested, evidence says no)
- **A mid-September price increase on key SKUs (e.g., P001 rising from ~$19 to ~$29) caused buyers to purchase at the higher price and then refund due to sticker shock or price mismatch, driving the H2-September refund spike.** - The H2-September refund spike is concentrated in products without mid-Sept price changes, and zero refunds cite price-related reasons, so the price-increase/sticker-shock mechanism is not supported.  
  _evidence: `Q5` row 1 `refund_cnt`=31; `Q5` row 1 `order_cnt`=240; `Q5` row 1 `refund_rate`=0.12916666666666668; `Q5` row 3 `refund_cnt`=5; `Q5` row 3 `order_cnt`=58; `Q5` row 3 `refund_rate`=0.08620689655172414_
- **Refunds are concentrated in one or two countries in H2 September due to local shipping delays, customs issues, or seasonality, not a global increase.** - Refunds in September H2 are spread across multiple countries and the refund rate is uniformly 1.0, so the increase is not concentrated in one or two countries.  
  _evidence: `Q6` row 1 `refund_cnt`=2; `Q6` row 4 `refund_cnt`=3; `Q6` row 6 `refund_cnt`=5; `Q6` row 9 `refund_cnt`=10; `Q6` row 11 `refund_cnt`=6; `Q6` row 14 `refund_cnt`=5_
- **The order mix shifted toward SKUs with inherently high refund rates in H2 September, so even with stable order volume, total refunds rose.** - Rejected: the high-refund-rate SKUs had fewer orders in H2 September than in H1 September while their refund dollars rose, indicating a per-order refund-rate increase rather than an order-mix shift toward those SKUs.  
  _evidence: `Q15` row 0 `refunds_h1`=29.0; `Q15` row 0 `refunds_h2`=145.0; `Q15` row 2 `refunds_h1`=75.0; `Q15` row 2 `refunds_h2`=405.0_
- **A surge in shipping/delivery support tickets in H2 September preceded and drove the refund increase, as customers cancelled after delays.** - The September ticket data contains no shipping/delivery ticket surge split by H1/H2 (all periods are null, with only download and refund categories), and Q20 has only a without_shipping_ticket group, so there is no evidence that shipping tickets preceded or drove refunds.  
  _evidence: `Q20` row 0 `period`=None; `Q20` row 0 `ticket_group`=without_shipping_ticket; `Q20` row 0 `orders`=30; `Q20` row 0 `refunds`=30; `Q20` row 0 `refund_rate`=1.0_

## Inconclusive / failed verification
- A product file release in mid-September introduced a defective version (wrong files or bugs), causing quality-related refunds for the affected product_ids. (rejected)
- Paid social (Meta) traffic quality deteriorated in H2 September: spend and clicks rose but sessions or landing_404s increased and conversion to orders fell, bringing low-intent visitors who refund at higher rates. (inconclusive)
- Broken landing pages (404s) in H2 September caused customers to order the wrong item or re-order, generating wrong-item or cancellation refunds. (rejected)

<details><summary>Q5 [H1] Refund rate (refunds divided by orders) for September, split by mid‑September price‑change status and half‑month (H1 vs H2). - 4 rows</summary>

```sql
WITH price_change_products AS (
  SELECT product_id
  FROM WHYDROP_FILES.pricing_changes
  WHERE to_date(date) BETWEEN '2026-09-01' AND '2026-09-14'
),
orders_enriched AS (
  SELECT
    o.order_id,
    to_date(o.date) AS order_date,
    o.product_id,
    CASE WHEN p.product_id IS NOT NULL THEN 1 ELSE 0 END AS has_mid_sept_price_change
  FROM WHYDROP_FILES.orders o
  LEFT JOIN price_change_products p
    ON o.product_id = p.product_id
  WHERE to_date(o.date) BETWEEN '2026-06-01' AND '2026-09-30'
),
order_counts AS (
  SELECT
    has_mid_sept_price_change,
    CASE WHEN to_date(order_date) BETWEEN '2026-09-01' AND '2026-09-14' THEN 'H1' ELSE 'H2' END AS period,
    COUNT(*) AS order_cnt
  FROM orders_enriched
  WHERE to_date(order_date) BETWEEN '2026-09-01' AND '2026-09-30'
  GROUP BY has_mid_sept_price_change, period
),
refund_counts AS (
  SELECT
    o.has_mid_sept_price_change,
    CASE WHEN to_date(r.date) BETWEEN '2026-09-01' AND '2026-09-14' THEN 'H1' ELSE 'H2' END AS period,
    COUNT(*) AS refund_cnt
  FROM WHYDROP_PG.refunds r
  JOIN orders_enriched o
    ON r.order_id = o.order_id
  WHERE to_date(r.date) BETWEEN '2026-09-01' AND '2026-09-30'
  GROUP BY o.has_mid_sept_price_change, period
)
SELECT
  o.has_mid_sept_price_change,
  o.period,
  o.order_cnt,
  COALESCE(r.refund_cnt, 0) AS refund_cnt,
  CASE WHEN o.order_cnt = 0 THEN 0 ELSE COALESCE(r.refund_cnt, 0) / o.order_cnt END AS refund_rate
FROM order_counts o
LEFT JOIN refund_counts r
  ON o.has_mid_sept_price_change = r.has_mid_sept_price_change
 AND o.period = r.period
ORDER BY o.has_mid_sept_price_change, o.period;
```
